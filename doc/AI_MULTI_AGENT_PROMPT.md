## 1. Мультиагентные чаты

### Вариант A: Клиентская маршрутизация (рекомендуется)

Клиент сам маршрутизирует сообщения между агентами:
- При отправке сообщения в групповой AI чат, клиент отправляет отдельные `ChatWithAIV2` запросы для каждого агента
- Ответы агрегируются в одном потоке
- Каждый ответ помечается `agent_id` и `agent_name`

**Преимущества:**
- Не требует серверных доработок
- Простая реализация
- Гибкость на клиенте

**Недостатки:**
- Больше сетевых запросов
- Нет кросс-агентного контекста

### Вариант B: Серверная маршрутизация

Добавить в `ChatWithAIV2Request`:
```protobuf
message ChatWithAIV2Request {
  string session_id = 1;
  string message = 2;
  repeated bytes images = 3;
  string agent_id = 4;
  repeated ToolCallRequestV2 tool_calls = 5;
  // Новое:
  repeated string agent_ids = 6; // Для мультиагентных чатов
}
```

Сервер обрабатывает:
1. Получает список `agent_ids`
2. Запускает параллельные запросы к каждому агенту
3. Стримит ответы с `agent_id` в каждом токене

**Преимущества:**
- Единый запрос от клиента
- Возможность кросс-агентного контекста

**Недостатки:**
- Сложная серверная логика
- Нужно управлять параллельными стримами

## 3. Рекомендации

### Для мультиагентных чатов:

**Рекомендую Вариант A (клиентская маршрутизация):**

1. Клиент хранит список `agent_ids` для чата
2. При отправке сообщения:
   ```kotlin
   // Клиентская логика
   for (agentId in agentIds) {
       scope.launch {
           AiV2ChatUseCase.chat(
               userId = userId,
               sessionId = sessionId,
               message = message,
               agentId = agentId,
               images = images
           )
       }
   }
   ```
3. Каждый ответ помечается `agent_id` в `ChatWithAIV2Response`
4. UI отображает ответы от разных агентов с эмодзи/именами

### Для сервера:

Минимальные доработки:
1. Убедиться, что `agent_id` возвращается в каждом токене стрима
2. Добавить `GetAIV2History` RPC для загрузки истории чата (если нужно)
3. Опционально: добавить `multi_agent` flag в `ai_chats_v2` для отличия от обычных чатов

## 5. Тестовые сценарии

1. **Один агент + текст** — базовый чат
2. **Один агент + изображение** — Vision анализирует фото
3. **Мультиагент (клиентский)** — два агента отвечают на один вопрос
4. **Reve генерация** — генерация изображения → image_url
5. **Tool calling** — агент вызывает инструмент → клиент отправляет результат
